# P3 Single-server AmneziaWG Implementation Plan

Status: In progress. The offline process-health slice started on 2026-08-24.

## Goal

Qualify one GL-MT6000 and one VPS as a `single-site core-ready` system. P3
combines the P2 production dataplane with the pinned AWG2/OpenWrt tuple, while
keeping WAN as the default route and VPN-class traffic fail-closed.

## Boundaries

- No production API or web UI; P4 owns the local control plane.
- No mobile peer lifecycle; P8 owns the versioned forced-command protocol and
  one-time profile delivery.
- No multi-server failover; P9 owns that field gate.
- Secret bytes never enter Git, command-line arguments, logs, inventory or
  support artifacts.
- Router and VPS mutation requires explicit target inventory, strict SSH host
  key verification, a recovery path and a reviewed commit-confirm boundary.

## Implementation sequence

### P3.1 Restricted server-agent foundation

- Preserve `server-agent version --json`.
- Add `server-agent health --json` as a local, process-scoped liveness command.
- Expose no HTTP listener, shell execution, configuration mutation or secret
  input in this slice.
- Reject every unimplemented operation and malformed argument list.

Acceptance: stable schema-versioned JSON, explicit `scope=process`, exact CLI
allowlist, encode failure is non-zero, Go unit tests and the repository verify
batch pass.

### P3.2 Pinned VPS deployment

- Define a non-secret inventory and immutable deployment bundle contract.
- Implement idempotent install/upgrade, restricted SSH access, service unit,
  IP forwarding/firewall configuration and compensation on partial failure.
- Add AWG interface, handshake and egress health without exposing key material.

Acceptance: two applies converge, a failed step compensates to the previous
state, the admin surface has no public HTTP port, and password/root SSH are
disabled after the recovery account is proven.

### P3.3 Router peer and endpoint routing

- Install the exact verified AWG2 packages on GL-MT6000 using the existing
  rollback-safe hardware smoke as the precondition.
- Configure `route_allowed_ips=0` and an endpoint host route through WAN before
  tunnel activation.
- Bind the real tunnel to the P2 per-server mark/table slot without changing
  the system default route.

Acceptance: tunnel absence retains terminal fail-closed routes; endpoint and
router management remain reachable through WAN.

### P3.4 Router package lifecycle

- Package the `linux/arm64` `routerd` binary as
  `routerd_<version>_aarch64_cortex-a53.apk`.
- Verify install, upgrade, remove, UCI preservation, boot ordering and LKG
  recovery on the exact firmware/kernel tuple.

### P3.5 Physical acceptance

- Run behind the existing ISP router/ONT before any primary-WAN cutover.
- Repeat selective egress, DNS/IPv6/QUIC, MTU, AWG-down packet capture, reboot,
  Ethernet recovery and package lifecycle checks.
- Record CPU/RAM/flash and throughput as measurements, not assumptions.

Exit gate: one physical router and one real VPS pass the complete P3 evidence
bundle; only then may the project claim `single-site core-ready`.

## External inputs still required

- Resettable GL-MT6000, exact firmware/kernel snapshot, wired recovery path and
  strict `known_hosts` material.
- One VPS inventory, recovery account and out-of-band provider console.
- Approved public endpoint and non-conflicting tunnel IPv4/IPv6 ranges.
- Secret key material supplied outside Git after the deployment contract is
  implemented and reviewed.

## Validation batch for the first slice

1. `go test ./internal/serveragentcmd ./internal/versioncmd`
2. `scripts/dev.ps1 -Command verify`
3. Independent security review of the command surface and output schema

No live router, VPS, Windows route or VPN state is changed by P3.1.
